# Deployment

## CI/CD
- **Not configured.** No `.github/workflows/`, no `codemagic.yaml`, no Fastlane, no Bitrise config. All builds/releases are currently manual, run from a developer machine. If asked to set up CI/CD, this is a from-scratch task — there's no existing pipeline to extend or mirror (the sibling `adopals-app/` web project does have Azure Static Web Apps GitHub Actions workflows, but that's a different deploy target and not reusable as-is for a Flutter mobile build).

## Android
- Application ID: `com.solidevelectrosoft.adopals` (see `android/app/build.gradle.kts`).
- `minSdk 23`, `targetSdk`/`versionCode`/`versionName` all derived from the Flutter tool (`flutter.targetSdkVersion` etc.) — don't hardcode these.
- No `key.properties` / release keystore found in the repo — release signing is not yet set up. A release build (`flutter build appbundle`) will currently fall back to debug signing unless signing config is added.
- Build commands:
  - Debug APK: `flutter build apk --debug`
  - Release APK: `flutter build apk --release`
  - App Bundle (for Play Store): `flutter build appbundle --release`

## iOS
- Bundle ID: `com.solidevelectrosoft.adopals` (see `ios/Runner.xcodeproj/project.pbxproj`).
- No `exportOptions.plist` found — archiving/exporting for TestFlight/App Store is not yet scripted; would currently be done manually through Xcode Organizer.
- Build commands:
  - Simulator/dev build: `flutter build ios --debug` (or `flutter run -d <simulator>`)
  - Release/archive: `flutter build ipa --release` (requires signing configured in Xcode first — no CLI-only signing setup exists yet)

## Firebase config per platform
- Config files are generated by `flutterfire configure` (`google-services.json` for Android, `GoogleService-Info.plist` for iOS/macOS) — see `firebase.json` for the exact output paths per platform. Regenerate via `flutterfire configure` rather than hand-editing if the Firebase project config changes.

## Local dev launch
- `./dev.sh` (or double-click `dev.command` on macOS) — interactive script that lists booted/available iOS simulators and Android emulators, boots one if needed, waits for it to be ready, then runs `flutter run -d <device>`. Prefer this over raw `flutter run` when you need to pick a specific device interactively.

## Troubleshooting
- **Stale build errors / plugin registration issues**: `flutter clean && flutter pub get`, then rebuild. Clears `build/` and `.dart_tool/` (both gitignored, safe to delete).
- **iOS pod issues**: `cd ios && pod install --repo-update` (requires CocoaPods; `ios/Pods/` is generated, gitignored, safe to delete and reinstall).
- **Firebase options mismatch after adding a platform**: re-run `flutterfire configure` rather than editing `lib/firebase_options.dart` by hand.
- **Release build signing errors**: expected — see Android/iOS sections above, signing is not yet configured. This needs to be set up (keystore + `key.properties` for Android, a distribution certificate + provisioning profile for iOS) before a real release build will succeed.
