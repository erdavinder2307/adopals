# Firebase

## Project
- Firebase project: `animalpedia-4f75b` (see `firebase.json` / `lib/firebase_options.dart`).
- Shared with the `adopals-app` web project — same backend, same Firestore data. Check `../adopals-app/CLAUDE.md` and `../adopals-app/functions/main.py` before changing data shapes; a change here can break the web app.
- `lib/firebase_options.dart` is generated by `flutterfire configure` — regenerate via that command if you add a platform or rotate config, don't hand-edit.
- Platforms configured: Android, iOS, macOS, web, Windows (per `firebase.json`).

## Auth providers in use
- Email/password (`firebase_auth`).
- Google Sign-In (`google_sign_in`).
- Apple Sign-In (`sign_in_with_apple`), with a manual nonce/SHA-256 flow via `crypto` — see `lib/screens/authentication/login_screen.dart`.
- Secure local storage of credentials/tokens via `flutter_secure_storage`.

## Firestore collections in use
| Collection | Written/read from | Purpose |
|---|---|---|
| `users` | `theme_service.dart`, `buyer_profile_screen.dart`, `pet_details_screen.dart` | User profile doc, keyed by Firebase Auth `uid`. Known fields: `theme`, `name`, `categoriesPref` (list of `{name}`). |
| `pets` | `buyer_dashboard_screen.dart`, `pet_details_screen.dart` | Pet listings, keyed by pet id. See `PetModel` in `lib/models/pet_model.dart` for the full field shape (`price`, `quantity`, `category`, `breed`, `photos`, `createdBy`, `availabilityStatus`, etc.) — this is the canonical shape, kept in sync by hand with the web app's pet model. |
| `carts` | `pet_details_screen.dart` | One cart doc per user, keyed by `uid`. **Note**: `lib/models/cart_item.dart` and `lib/services/cart_service.dart` are empty stubs — cart read/write currently happens ad hoc in `pet_details_screen.dart`, not through a dedicated model/service. |
| `favorites` | `buyer_dashboard_screen.dart`, `pet_details_screen.dart`, `buyer_profile_screen.dart` | Query-based (not a subcollection): docs with `userId` and `petId` fields, queried via `.where('userId', isEqualTo: ...)`. |
| `recently-viewed-pets` | `buyer_dashboard_screen.dart` | Query-based, filtered by `userId`, used to reconstruct a recently-viewed pet list via `pets` lookups on the returned ids. |

## Firestore models
- `PetModel` (`lib/models/pet_model.dart`) is the only fully-implemented model. It hand-parses loosely-typed Firestore data (handles `price`/`quantity` arriving as int, double, or string; `category`/`breed` arriving as string, map, or `DocumentReference`). When adding fields, follow this defensive-parsing style — the backend is not guaranteed to send consistent types.
- No `freezed`/`json_serializable` — models are hand-written (see [flutter.md](flutter.md) build_runner section).
- Account deletion pattern (see `buyer_profile_screen.dart`): batch-delete `favorites` (per-doc), `carts/{uid}`, and `users/{uid}` together via `WriteBatch` — follow this batching pattern for any other bulk cleanup.

## Firebase Storage
- `firebase_storage` is a dependency but not yet exercised in `lib/screens/` beyond what's implied by pet `photos`/`thumbnails` URLs (which appear to be plain URL strings on the `PetModel`, not direct Storage API calls in this codebase — uploads likely happen from the web app / Cloud Functions side).

## Rules
- No `firestore.rules` / `storage.rules` file exists inside `adopals/` — security rules are managed from `../adopals-app/firestore.rules` / `storage.rules` since it's the same Firebase project. Don't create a second rules file here; if rules need to change, that's an `adopals-app` change.
